# Модель данных — предложение
- Club, User, ClubRole: клуб, аккаунт и права.
- Athlete: отдельная спортивная сущность; аккаунт может отсутствовать у исторического спортсмена.
- Group, AthleteGroupMembership: членство в группах с периодами действия.
- TestDefinition: дисциплина, фактическая дистанция, стиль/формат, метрика и направление лучшего результата.
- TestEvent: дата, определение теста, условия, статус, создатель.
- EventParticipant, Attempt: участник, номер попытки, числовое время, валидность, автор ввода.
- ResultSegment: этапы триатлона Swim/T1/Bike/T2/Run; total и правила проверки уточняются.
- ImportBatch, SourceRecord: происхождение, исходное значение и результат импорта.
Позже: MembershipPlan, AthleteMembership, Benefits.
Время предлагается хранить целым количеством сотых секунды; дистанцию — числом в метрах с точностью для нестандартных дистанций. Текстовое форматирование только на экране.
Статус спортсмена, аккаунта и абонемента — разные сущности. Конкретные enum пока не утверждены.
# Правила аналитики — предложение
- Официальное время старта: минимальное время валидной попытки спортсмена.
- PB: минимальное официальное время среди сопоставимых опубликованных тестов.
- All-Time: одна лучшая запись на спортсмена в выбранной категории.
- Latest: последний опубликованный сопоставимый тест; правило для одинаковой даты ещё открыто.
- Улучшение: предыдущее время минус текущее; процент = эта разность / предыдущее время × 100. Нет предыдущего результата — нет процента.
- DNS/DNF/DSQ не превращать в 0 секунд и не включать в PB.
- Рейтинг при равном времени и дата рекорда при одинаковом PB — открытые правила.
# UX — предложение
Спортсмен: Главная → Результаты → Детали/Прогресс → Рейтинг → Профиль.
Тренер: Тесты → Новый тест → Участники → Ввод попыток → Черновик → Публикация.
Админ: Спортсмены → Группы → Пользователи и доступ → Справочники.
Карточки KPI, большие поля ввода, фильтры, касание точки графика, понятный контекст сравнения. Не переносить широкие BI-таблицы целиком на телефон.
Новые wireframes пока не созданы. Цвета teal/gold из обсуждения — направление; точные цвета и логотип предстоит проверить по форме.
# Стек — предложение из обсуждения
Next.js + TypeScript; Supabase/PostgreSQL/Auth/RLS; Vercel. Окончательное решение, стоимость, регион данных и размещение ещё не подтверждены.
Бизнес-коды независимы от языка; UI-переводы отдельные, имена спортсменов не переводятся автоматически.
# Результат этапа Design
ERD v1, data dictionary, проверенная матрица прав, wireframes ключевых мобильных сценариев, правила сравнений и схема авторизации.
